# ModernBERT reranking

## Scope

The owned runtime supports `Alibaba-NLP/gte-reranker-modernbert-base` as a rerank capability on `ModelFamily`. The embedding runner and the `gte-modernbert-base` CLS-plus-L2 output remain unchanged. Reranking is fp32-only on the CPU correctness path and the block-resident Metal path.

The CLI selects reranking with `--rerank-requests`. Each JSONL row has `id`, `query`, and a non-empty `documents` array. `--scores-out` writes one raw-logit array in document order. `--reference` accepts the same `{id, scores}` JSONL emitted by `bench/eval-coir/reference_rerank.py` and enforces Pearson and tie-aware top-1 gates.

## Token path verification

The checkpoint's `tokenizer_config.json` specifies right truncation, longest-first pair truncation, right padding, an 8,192-token model maximum, and the standard `[CLS] query [SEP] document [SEP]` post-processor. Runtime tokenizer padding is disabled; graph batches explicitly fill with token ID 50283 and mask every padded position from attention and masked-mean pooling. Buckets use the combined pair length.

Before implementing the graph path, this pair was encoded with Transformers 5.12.1 `AutoTokenizer` and cross-checked against the Rust `tokenizers` pair input:

- query: `what is rust?`
- document: `Rust is a systems programming language.`
- IDs: `[50281, 5371, 310, 20035, 32, 50282, 51, 461, 310, 247, 2718, 10717, 3448, 15, 50282]`

The committed `fixtures/rerank-reference.json` records this check and a second pair. The ignored end-to-end fixture test validates both IDs and raw scores when `MODERNBERT_RERANK_MODEL` points at the checkpoint.

## Classification head found in the checkpoint

The checkpoint differs from its embedding sibling in an important way: `gte-modernbert-base` embeds the CLS token, while the reranker config sets `classifier_pooling: "mean"`. Transformers masks padding, averages the final normalized encoder states, and then applies the sequence-classification head. The task's original CLS wording was corrected after inspecting the config, safetensors, and Transformers forward path.

The loaded tensors and exact inference path are:

| Stage | Tensor / behavior | Shape |
|---|---|---:|
| Pool | attention-mask-weighted mean | 768 |
| Dense | `head.dense.weight`, no bias | 768 x 768 |
| Activation | exact-erf GELU | 768 |
| Norm | `head.norm.weight`, epsilon 1e-5, no bias | 768 |
| Projection | `classifier.weight` | 1 x 768 |
| Bias | `classifier.bias` | 1 |

The output is the single f32 regression logit. The Python reference reads `model(...).logits[:, 0]`; it does **not** apply sigmoid. The owned runtime therefore writes raw logits too.

CPU runs the encoder and the same masked-mean/head math in Rust fp32. Metal extends the resident MPSGraph through masked mean, dense, GELU, norm, and classifier, returning one score per pair rather than reading encoder hidden states to the host. Rerank plans are separately keyed from embedding plans. Explicit O0 compilation is the default, graph revision 3 participates in cache identity, and one `.mpsgraphpackage` is stored per combined-length bucket shape.

## Scoring gates

Reference scores were generated by an executed Transformers CPU run over the first 50 sorted cosqa requests, truncated to 20 dense candidates each (1,000 pairs), with max length 512 and batch size 8. Candidate scores were compared with `compare_rerank_scores.py`. CPU execution was split into two 25-request processes to stay within the command time limit; their score JSONL files were concatenated before the aggregate comparison.

| Provider | Shapes | Overall Pearson | Tie-aware top-1 | Gate |
|---|---|---:|---:|---|
| CPU / Accelerate fp32 | exact | 0.9999999999951004 | 1.00 | pass |
| Metal / MPSGraph fp32 | bucketed, explicit O0 | 0.9999999999969084 | 0.98 | pass |

The required thresholds are Pearson >= 0.999 and tie-aware top-1 >= 0.98. One cosqa request has constant reference scores, so its per-request correlation is undefined; the aggregate Pearson still covers all 1,000 aligned pairs. The CPU raw top-1 rate was 0.98, and the Metal raw top-1 rate was 0.96. Exact top ties account for the difference from tie-aware agreement.

The committed snippet's Transformers scores are `3.0635757446289062` and `-1.2756527662277222`. Executed owned scores were `[3.063575, -1.2756505]` on CPU and `[3.0635748, -1.2756476]` on Metal.

## Serving measurements

### Contended-local

These are local development-machine numbers, explicitly labeled **contended-local** rather than M1 graduation numbers. The command repeated one real cosqa query with 50 documents 20 times, used fp32 Metal, combined-length buckets, explicit O0 execution, and a warm package cache containing all ten sequence buckets.

| Request shape | Repeats | p50 | p95 | Batch throughput |
|---|---:|---:|---:|---:|
| 1 query x 50 documents | 20 | 505.34 ms | 651.77 ms | 94.45 pairs/s |

The executed run scored 1,000 pairs in 10.5875 s. Request-local fixed eight-row buckets reported 35.46% padding waste because tail batches are not coalesced across independent queries; all padded keys remained masked in attention and all padded rows were omitted from returned scores.

### Locked M1

The locked run used `<bench-host>` (Apple M1 Max, 64 GiB, macOS 26.5.2 build `25F84`) and binary SHA-256 `3fae0455ccc650c1b597c7bc4b8c4dc8d08c224b45d471128fe360b9cddc9db3`. A non-measured prime process created all ten policy-v1 packages. Each measured row is then a fresh process reusing that warm cache, with fp32 Metal, explicit O0, maximum length 512, and the fixed eight-row combined-length buckets.

The committed fixture [`fixtures/cosqa-rerank-1x50-repeated.jsonl`](fixtures/cosqa-rerank-1x50-repeated.jsonl) repeats one real cosqa query with its 50 dense candidates 20 times, giving both 20 request-latency samples and a 1,000-pair throughput set. Its committed Transformers reference is [`fixtures/cosqa-rerank-1x50-repeated-reference.jsonl`](fixtures/cosqa-rerank-1x50-repeated-reference.jsonl). Every process passed Pearson and tie-aware top-1 gates.

| Process | Requests x documents | p50 | p95 | 1,000-pair wall | Throughput | Pearson | tie-aware top-1 |
|---|---:|---:|---:|---:|---:|---:|---:|
| HIT r1 | 20 x (1 x 50) | 242.15 ms | 242.94 ms | 4.844 s | 206.42 pairs/s | 0.999999999995 | 1.00 |
| HIT r2 | 20 x (1 x 50) | 242.43 ms | 243.03 ms | 4.849 s | 206.25 pairs/s | 0.999999999995 | 1.00 |

The two fresh processes agree within 0.3 ms at p50 and 0.1 ms at p95. Their locked throughput is about 2.18x the 94.45 pairs/s contended-local observation. The AFT budget of p50 <= approximately 0.5 s for 50 documents **passes** with 242.43 ms worst-repeat p50, using only 48.5% of the budget.

macmon started, produced an idle sample, and waited another two seconds before each process. The inference-window summaries are:

| Process | samples | mean GPU use | mean GPU power | max GPU power |
|---|---:|---:|---:|---:|
| HIT r1 | 31 | 95.2% | 36.97 W | 44.30 W |
| HIT r2 | 31 | 94.0% | 36.38 W | 40.20 W |

Every timed process acquired `$SYNAPSE_BENCH_ROOT/bench.lock`, verified that `Runner.Worker` was absent, and used trap-based macmon cleanup before releasing the lock. Raw logs remain under `$SYNAPSE_BENCH_ROOT/bench-tools/unified-rt-serving/results/m1-rerank/`; result JSON and the macmon-derived summary are committed under `results/m1-rerank/`.

The fixture is reproducible from the first row of the canonical cosqa `gte-rerank-requests.jsonl`: duplicate its 50-document request 20 times with IDs `q20105-run-00` through `q20105-run-19`, then score the single request and duplicate its score row under the same IDs. The executed reference command was:

```sh
uv run --group reference reference_rerank.py \
  --requests /tmp/cosqa-rerank-1x50.jsonl \
  --out /tmp/cosqa-rerank-1x50-reference.jsonl \
  --max-length 512 --batch-size 8 --device mps
```

## Tests and reproduction

- `modernbert_rerank_matches_transformers_reference_fixture_on_cpu` checks pair IDs and end-to-end CPU logits against the committed Transformers snippet.
- `modernbert_rerank_static_feeds_survive_multiple_calls` exercises different Metal shapes before rescoring the fixture and compares against a fresh-process invocation, guarding static-feed lifetime and graph-cache reuse.
- `rerank_gate_uses_pearson_and_tie_aware_top1` keeps the ranking gate semantics under ordinary CI.

Example:

```sh
spike-unified-rt \
  --model /path/to/gte-reranker-modernbert-base \
  --tokenizer /path/to/gte-reranker-modernbert-base/tokenizer.json \
  --rerank-requests /tmp/cosqa-rerank.jsonl \
  --scores-out /tmp/owned-rerank-scores.jsonl \
  --reference /tmp/transformers-rerank-scores.jsonl \
  --out /tmp/owned-rerank-result.json \
  --device metal --dtype f32 \
  --shapes bucketed --execution explicit \
  --package-cache /tmp/owned-rerank-packages \
  --max-length 512
```

## Open items

- Evaluate f16 separately. Existing M1 evidence makes gte f16 regressive, so reranking rejects f16 rather than silently changing precision.
- Add batch-dimension tail buckets or safe cross-request coalescing if rerank padding waste becomes a serving bottleneck.
- Add Qwen3-class rerankers after their sequence-classification architecture and scoring conventions are independently verified.
